# 06 · 多站点平台:站主 + 每台终端的独立网盘(2026-09-06 起)

> 让 47 的公网入口服务**多台终端**:你自己、你的多台电脑、朋友们各自部署一套"本地 FileBrowser + frpc",彼此完全隔离,各自管各自的 admin/guest,共享 47 的出网。
> 配套工具:`pan-ctl`(47 上站主用)+ `deploy-site.ps1`(Windows 一键部署)。

## 角色模型

| 角色 | 是谁 | 管什么 |
|---|---|---|
| **站主(owner)** | 你(拥有 47) | 在 47 上建/停/删站点、分配端口与 token、重置密钥、看在线。**通过命令行 pan-ctl**,不做网页控制台 |
| **站点管理员(site-admin)** | 每台接入的终端主人 | 在自己那台电脑的网盘里管**自己的 guest**(FileBrowser 原生:建号/scope/只读) |
| **guest** | 各站管理员的朋友 | 只读访问该站 公共 |

> 为什么 FileBrowser 内部不做三层嵌套:FileBrowser 是扁平账号模型,表达不了 owner→admin→guest。
> 落地:owner 管的是"站点"(基础设施),admin 管的是"自己实例里的用户"。隔离靠四层:独立端口 + 独立 frps/token + 独立 FileBrowser db + 独立电脑。

## 架构

```
站主:47 上 pan-ctl + /etc/frp-sites/sites.conf(注册表,root 600)

站点1 main(站主自身,legacy):nginx 8081 → frps(443)→ 隧道 → 站主电脑 filebrowser(E:\NetDist)
站点N     (pan-ctl 建):nginx 80xx → fbproxy-N → frps-N(700x,独立 token)→ 隧道 → 站点N 电脑 filebrowser

每站端口(pan-ctl 自动分配,index>=2):
  HTTP(对外)   = 8080+index    例 demo=8082
  frps 控制     = 7000+index    例 7002(公网,独立 token)
  frp 数据口    = 8090+index    例 8092(仅 nginx 回环访问,不占公网)
  fbproxy(回环) = 9000+index    例 9002
```

## 站主操作(47 上)

```bash
pan-ctl add-site <name>            # 建站;结束打印"接入凭据",线下发给该站点主人
pan-ctl ls                          # 列表:各站 http/frps 端口、token 前 6 位、在线状态
pan-ctl show <name>                 # 重看某站凭据
pan-ctl stop <name> / start <name>  # 停/启某站隧道(stop 后该站公网 502)
pan-ctl reset-token <name>          # 换 token(旧 frpc 掉线,需同步 admin)
pan-ctl rm-site <name>              # 删除站点
```
首次:在 47 写公网 IP:`echo <SERVER_IP> > /etc/frp-sites/public_ip`。

**add-site 给 site-admin 的凭据**:serverAddr / serverPort / remotePort / token(线下发,勿进仓库)。

## 客户端接入(站点管理员,Windows)

拿到站主发的凭据后,运行(下载 `config/deploy/deploy-site.ps1`,放一个含
filebrowser.exe / frpc.exe / nssm.exe 的目录,或让站主发一个已备好的压缩包):

```powershell
powershell -ExecutionPolicy Bypass -File deploy-site.ps1 `
    -SiteName <站名> -ServerAddr <SERVER_IP> -ServerPort <700x> -RemotePort <809x> `
    -Token <token> -DataDir D:\myNetDisk -AdminPassword 你的密码 -EnablePointer
```
脚本自动:建网盘根(公共/私人)→ 初始化独立 db → 设 admin →(可选)开指针 →
注册服务 `FB-<站名>` + `FRP-<站名>`(开机自启 + 崩溃 5s 重启 + 断线自动重连)→ 输出地址。
完成后浏览器访问站主告知的 `http://<SERVER_IP>:<80xx>` 用 admin 登录,可自行 `FileBrowser 设置→用户` 建 guest。

> guest 建法(任一站 FileBrowser 内):管理员登录 → 设置 → 用户 → 新增;
> 账号 scope 填 `/公共`、只保留"下载"权限 = 只读看公共。

## 指针(junction / 符号链接):不复制,把别处文件夹挂进网盘

- **总开关**:每个站点独立,`filebrowser config set --followExternalSymlinks`(deploy 脚本 `-EnablePointer` 已含)。
  开启后 FileBrowser 启动会有安全 WARNING——意味着允许跟随指向网盘根外的链接。
- **建指针(重要:用符号链接 mklink /D,不是 junction!)**:
  - junction(`mklink /J`)对 FileBrowser"列目录"会 500(实测),只支持直接下载;
  - **目录符号链接 `mklink /D`(需管理员,或开开发者模式)列目录+下载都正常**(实测 200)。
- 示例(管理员 cmd 或提权 PowerShell):
  ```cmd
  mklink /D "D:\myNetDisk\公共\电影外部" "E:\downloads\电影"    :: 想给 guest 看的 → 放 公共
  mklink /D "D:\myNetDisk\私人\我的备份" "F:\backup"             :: 只想自己看 → 放 私人
  ```
- **安全边界**:符号链接放进 `公共/` = 该站 guest 也能顺着访问目标目录!
  `私人/` 下的只有 admin(scope /)能进。放公共的链接务必只指向"愿意公开"的目录。
- 无需复制/不占空间;目标目录内容即网盘内容。

## ⚠️ 云防火墙 + 系统防火墙(踩过的坑,务必看)

阿里云轻量有**两层防火墙**:
1. **阿里云控制台"防火墙"页**(云层);
2. **47 系统内的 ufw**(`ufw status`,iptables)——**默认 deny incoming**。

> 教训:曾在控制台"新增 7000/7500"显示已启用却不生效,其实是**47 内 ufw 没放行**,包到网卡就被丢。
> 排查"某端口外网不通":先 `ssh 47 'ufw status'` 看有没有 ALLOW,没有就
> `ufw allow <ports>/tcp`。云层规则其实早生效了。

当前已放行段(ufw + 云):`7000-7010/tcp`、`8082-8090/tcp`(frps 控制口与各站 HTTP 口)。

## 文件与位置

| 东西 | 位置 |
|---|---|
| 站主工具 | 47 `/usr/local/bin/pan-ctl`(模板在仓库 `config/deploy/pan-ctl`) |
| 站点注册表 | 47 `/etc/frp-sites/sites.conf`(root 600,含真实 token) |
| 每站 frps | 47 `/etc/frp/frps-<站>.toml` + systemd `frps-<站>.service` |
| 每站 fbproxy | 47 systemd `fbproxy-<站>.service`(参数化脚本 `/srv/fbproxy.py`) |
| 每站 nginx | 47 `/etc/nginx/sites-available/pan-<站>`(独立 server,listen 80xx) |
| 客户端脚本 | 仓库 `config/deploy/deploy-site.ps1` |
| fbproxy 参数化 | 仓库 `config/fbproxy.py`(argv:监听口 转发口) |

## 故障排查

| 现象 | 查 |
|---|---|
| 某站公网打不开 | 该站电脑是否开机;47 `systemctl status frps-<站> fbproxy-<站> nginx`;`pan-ctl ls` 在线状态 |
| 端口不通 | 先 `ssh 47 'ufw status'` 确认 ufw 放行(见上);再看云防火墙页 |
| 某站连不上隧道 | 该站 `frpc` 日志;token 是否与 `pan-ctl show` 一致(改过就 reset) |
| 指针目录列不出/500 | 确认用的是 `mklink /D` 符号链接而非 junction;确认该站开了 followExternalSymlinks |
| i18n 登录页回英文 | 该站 FileBrowser 不是 2.63.23(升级会改资源 hash,详见 docs/03) |
| 站1(8081)被误伤? | 站1 是 legacy 单进程,pan-ctl 不碰它;改配置前 `cp` 备份、`nginx -t` |

## 验收(交付时给站主三步)

1. 浏览器 `http://<SERVER_IP>:8081` guest 下小文件 = 原站没坏;
2. 浏览器 `http://<SERVER_IP>:8082`(demo 站)admin 登录翻一翻 = 多站点通;
3. 网盘 `公共/` 里那个"符号指针"文件夹,点进去能看到外部文件并可下载 = 指针通。
