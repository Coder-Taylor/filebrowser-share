# 04 · 大文件上传经验（GB 级）

## 问题

直接 `scp 一个 2.2GB 的 ISO`，传到约 400MB 时被服务器 **`Connection reset by peer`** 掐断；scp 没有续传，每次都要从头重传。

## 方案：分片上传 + 服务器拼接 + md5 校验

把大文件切成小段（每段短连接，断了只补那一小段），传完在服务器拼回原文件。

```bash
# 1) 本地切片（300MB/段 → pr_part_00、01、…）
split -b 300M -d -a 2 "Pr 2024 v24.5.0.iso" pr_part_

# 2) 逐段上传到服务器临时目录 /tmp/pr_parts（每段一个短连接，可加自动重试）
scp -i <KEY> pr_part_00 root@<SERVER>:/tmp/pr_parts/
scp -i <KEY> pr_part_01 root@<SERVER>:/tmp/pr_parts/
#   … 断在哪段就只重传那段

# 3) 服务器拼接并移动到网盘根目录
ssh root@<SERVER> "cd /tmp/pr_parts && cat pr_part_* > combined.iso \
  && mv -f combined.iso '/srv/alist/storage/公共/常用软件/Adobe/Pr 2024 v24.5.0.iso' \
  && rm -f pr_part_*"

# 4) 校验：字节数与 md5 双对拍（本地、服务器各算一次 md5，应一致）
md5sum "Pr 2024 v24.5.0.iso"                                     # 本地
ssh root@<SERVER> "md5sum '/srv/alist/storage/…/Pr 2024 v24.5.0.iso'"  # 服务器
```

## 实测数据（本次 2.35GB ISO）

- 8 段 × 300MB（末段 154.6MB）
- 拼接后字节 2,356,633,600 == 本地源文件字节
- 本地 md5 == 服务器 md5（完全一致，无损）

## 其它要点

- 传的时候别同时移动源目录（上传过程读的是源文件）。
- 传完建议保留源文件，等对方确认可用再本地删。
- 若带宽上行只有 ~100Mbps，2.35GB 理想也要 3 分钟+；分片后单段 300MB ≈ 30 秒，失败损失小。
