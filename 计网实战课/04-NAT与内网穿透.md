# 计网实战课 · 第四课:NAT 与内网穿透的完整原理

> 配套:第一课(IP/包)、第二课(连接)。本课讲透"为什么你电脑没公网 IP"和"frp 凭什么能通"。

## 一、公网 IP 与私网 IP

- **公网 IP**:全局唯一、任何人可直达 → 本项目只有 47 有(`<SERVER_IP>`)。
- **私网 IP(RFC 1918)**:`10.x`、`172.16~31.x`、`192.168.x`。NAT 后的设备用这些,不对外路由。

## 二、NAT / NAPT:私网怎么"借"公网

- 一堆内网设备共享一个公网出口。路由器(NAT)维护一张**映射表**:
  ```
  内网(192.168.1.100:50001) ──► 公网出口(47.x:某高位端口)
  内网(192.168.1.101:50001) ──► 公网出口(47.x:另一个高位端口)
  ```
- **出站**:内网主动访问外网 → NAT 在表里记一条,并把回来的包对应回内网主机(靠端口区分谁是谁 → 就是第二课的四元组思想)。
- **入站**:外网主动连内网 → 表里没这条 → **丢弃**。

> 这就是你电脑"没公网 IP、别人拨不进来"的根本原因:你不是没有网络,是**躲在 NAT 后面,别人找不到你**。

## 三、内网穿透 = 借"出站"反向利用

NAT 放行出站 → **让内网设备自己主动拨一条出去**。主动方是你电脑 → 目的地是 47 → 建立后这条连接全双工,数据能双向走。

```
你电脑 ──(主动拨号,出站)→ 47
        ←──(这条连接上,47 可以把外面的请求传回来)
```

于是 47 成了你的"代言人":外人访问 47,47 沿这条**你主动建立的连接**把流量交给你。

**关键认知**:穿透不是"发你一个公网 IP",而是"借一条你主动拨出、可双向通信的 TCP 连接"。你的电脑始终没有公网 IP。

## 四、三种让内网设备被访问的方案

| 方案 | 做法 | 特点 |
|---|---|---|
| **端口映射** | 在 NAT 路由器上手动开一个公网口 → 指到内网某台机 | 直连、快;但设备要常开、暴露、每次手动配 |
| **中继隧道(frp,本项目)** | 内网拨一条 TCP 到有公网 IP 的 47,流量全走它 | 简单可靠、全走服务器带宽;但所有流量经服务器 |
| **UDP 打洞(P2P)** | 两端都主动向对方 NAT"钻洞",成功后直连 | 不经过服务器;但受 NAT 类型影响,可能打不通 |

本项目用**中继模型**:frps 在 47 当总机,frpc 在本地当分机。

## 五、frp 全链路(复习 + 加深)

```
朋友 → <SERVER_IP>:8081(nginx)
        → frps:443 上那条常驻隧道(你电脑拨进来的)
        → frpc → 127.0.0.1:8085(本地 FileBrowser)
```

- **frps 怎么知道有请求?** 不是轮询:frpc 启动时与 frps 建立**一条常驻 TCP 长连接 + 心跳保活**;frps 收到 nginx 转来的连接,在长连接上**主动下发控制消息**("有新客人,ID=7,去接"),frpc 再新建到本地的连接、两端接驳。
- **复用**:tcpMux 让一条物理隧道上跑多个逻辑流(同 HTTP/2 思想),十个人同时下载互不干扰。
- **数据方向**:下载时数据从你本地(上行)流出,经隧道到 47 再到朋友;**流经 47 但不落盘**,47 只是"口子 + 总机"。

## 六、安全视角:攻击面在哪

- 暴露在公网的只有 47(nginx:8081、frps:443、ssh:22)。
- 你的电脑 NAT 后 + filebrowser 只听 127.0.0.1 → **三层防护**:
  1. 无公网 IP、NAT 拒入站;
  2. 只听回环,局域网都够不着;
  3. 隧道有 token 认证,不知道 token 的 frpc 连不上。
- 公网扫描永远摸不到你电脑——这正是"把攻击面转移到一台随时可重置的云跳板"的收益。

## 带走三句话

1. 私网设备靠 **NAT 出站**上网,外网进不来 = 没公网 IP 的本质;
2. 穿透 = 内网**主动拨一条双向连接**给公网服务器,让它当代言人;
3. frps/frpc = 总机/分机,**请求靠长连接上主动下发,不是轮询**。
