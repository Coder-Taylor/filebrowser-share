# 计网实战课 · 第一课:数据包与分层

> 用 FileBrowser 共享网盘这个真实项目,从零学计算机网络。
> 每课一次只讲透一个主题,配本项目实例与自测。

## 本课要解决的问题

`E:\NetDist` 里一个 2.6G 文件,朋友点下载后拿到**一模一样**的 2.6G。这串 0/1 是怎么从你的硬盘"跑到"朋友硬盘的?

答案:不能整坨传,要**切成小块**,每个小块套上"信封",各自上路,最后按序号拼回原样。

## 为什么必须切成小块?(三大障碍)

1. **网络是共享的**:千万台设备共用线路,必须把数据切小、大家轮流用(类比单车道轮流过)。
2. **出错重传代价要小**:大块出错要整坨重传;切小后"哪块坏补哪块"。
3. **要能找路、能还原顺序**:小块要各自带地址,到达后按序号重组。

## 什么是"包"和"信封(头部)"

每个数据小块外面裹一层"信封",信封上写(这是"头部 header",里面是"数据"):

| 信封字段 | 类比 | 作用 |
|---|---|---|
| 目的 IP | 收件地址 | 路由器决定往哪转发 |
| 源 IP | 寄件人 | 对方好回信 |
| 目的端口 | 收件人姓名 | 同一台机上区分给哪个程序 |
| 序号 | 第几页 | 到达后按序拼回 |
| 确认号/校验 | 回执 | 丢了就重传 |

> 驿站(路由器)**只看信封指路、不拆内容**——这就是分层各司其职的起点。

## 分层与封装:信封套信封

```
你的程序:只关心内容(视频数据)
  ↓ TCP 层:套【传输层信封】(端口+序号+校验)
  ↓ IP 层:套【网络层信封】(源/目的 IP)
  ↓ 链路层:套【链路层信封】(网卡地址)
  ↓ 变成电信号上路
```

每层只干自己的活、把上层当黑盒 → 换网卡不用改软件、换浏览器不用换网线。这就是"封装/分层"。

## 为什么切 1460 字节?(MTU / MSS)

链路层一次能放的"一帧"有上限:**以太网 MTU = 1500 字节**(历史定下的兼容标准;权衡:太大→重传贵、占线久;太小→头占比浪费)。

```
1500(链路一帧)
- 20(IP 头)
- 20(TCP 头)
= 1460 字节  ← TCP 每次装数据的上限,称 MSS(最大段大小)
```

> 若 PPPoE 拨号,帧更小(MTU 1492)→ MSS = 1452。

## 一次完整旅行(串起来)

```
filebrowser 读 E 盘 → 切成 1460B×178 万个
每个小块:套 TCP 头 → 套 IP 头(寄 47.94.146.53)→ 套链路头上线路
你的网卡 → 路由器(剥链路头,看 IP 指路)→ 校园网逐层转发
→ 47 → frp 隧道 → 朋友端 → 朋友网卡逐层撕信封
→ TCP 按序号排好、查缺补漏 → 完整交给浏览器
```

你传的不是一个 2.6G 文件,而是 **178 万个 ~1.5KB 的小包**,各自带信封,到齐按序号拼回。

## 带走三句话

1. 网络传的是**切好的小包**,每个带"写给谁、第几块"的信封(头部);
2. 路由器只看信封指路、不拆内容 → **各层各司其职**;
3. 数据被**层层套信封**(应用→TCP→IP→链路),接收端逐层撕开 = 封装/分层。
