# 计网实战课 · 第八课:网络安全入门

> 配套:第四课(攻击面)。本课用本项目讲清安全的三个基本问题:认证、授权、加密,以及"谁在公网上挨打"。

## 一、安全三件事,别混

| | 解决什么 | 类比 | 本项目 |
|---|---|---|---|
| **认证(Authentication)** | 你是谁 | 出示身份证 | 登录用户名密码 → 发 token |
| **授权(Authorization)** | 你能干什么 | 门禁等级 | guest scope=/公共 只读;admin scope=/ |
| **加密(Encryption)** | 路上别人看不看得懂 | 密封信 | HTTPS/TLS(本项目还没做,见下) |

### 认证:密码怎么存才对
- 绝不能存明文:数据库泄露=全泄露。
- 存**哈希(bcrypt)**:单向函数,可验证不可还原。改密时直接覆盖哈希,**没人能"找回"明文**(包括管理员本人)。
- Token(JWT):服务器签名的通行证,带有效期(本项目 2h),过期待续(`/api/renew 401` 就是续期失败)。

### 授权:最小权限 + 隔离
- guest 只有 download、scope 锁在 `/公共`;越权访问 `/私人` 返回 **404 而非 403** → 故意不暴露私人区存在。
- 架构级隔离:filebrowser 只听 127.0.0.1 + NAT + 隧道 token → 攻击面三层收窄。

## 二、加密:为什么明文 HTTP 是短板

本项目 `http://<SERVER_IP>:8081` 是**明文**:
- 登录时密码、下载的内容在公网传输 = **可被中间人嗅探**(同网络的人/网关能看到)。
- 解决 = **HTTPS(TLS)**:握手时交换密钥(非对称),之后数据对称加密传输,中间人看到的是密文。
- 代价:需要证书(Let's Encrypt 免费) + 让 frp 让出 443(本项目待办)。

> 威胁分级:可信任小圈子 + 家用/校园网 = 风险低;但"登录凭据在公网明文"始终是真实隐患,README 里记为"按需上 HTTPS"。

## 三、谁在公网上挨打:攻击面

- **暴露 = 能被扫描到 = 才需要防**。公网扫描器天天扫全网 IP 的常见端口。
- 你的电脑:无公网 IP + NAT 拒入 + filebrowser 只听回环 → **扫描器根本看不见它**。
- 47:只开放需要的口(8081/443/22 + 各业务),**安全组/防火墙**入站白名单;隧道 frps 还要 **token 认证**。
- 已暴露的口子做最小化:22 关密码登录用密钥、非必需端口不放行。

## 四、本项目踩过的安全相关坑(经验)

- 阿里云**后加的安全组规则显示"已启用"却不生效**(7000/7500 都超时)→ 预置端口(80/443/22)无此问题 → 借 443。教训:云防火墙规则要实测生效,别只看控制台。
- **脱敏**:仓库不存真实 IP/密码/token(模板占位),运行实例放 git 忽略的 runtime/ → 防"提交=泄库"。
- 密码不能"找回"只能重置;明文密码只出现在"给对应读者"的说明里(guest 密码写在公共说明里给 guest 看)。

## 带走三句话

1. 分清**认证**(你是谁)/**授权**(你能干嘛)/**加密**(路上保密);
2. 明文 HTTP 是短板 → 想认真安全就上 HTTPS;密码要哈希存、越权要 404 藏、暴露面要最小;
3. 安全第一原则:**不在公网的东西不用防**——把数据留在 NAT 后的电脑,只让一台可丢弃的云服务器露头。
