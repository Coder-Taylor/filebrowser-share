# 计网实战课 · 第六课:断链自愈与断点续传

> 配套:第二课(TCP 可靠/连接)、第三课(HTTP Range/206)。本课讲本项目"抗网络抖动"的两层完整机制。

## 一、网络抖动下会发生什么

校园网/无线会突然断几秒。这时:

1. **TCP 连接死亡**:正在传输的连接,双方等不到 ACK,最终超时被判定断开(连接状态:序号、窗口全作废)。
2. **正在下载的任务中断**:朋友的下载请求挂在死连接上 → 失败。

要恢复,需要**两层配合**:传输层"重连" + 应用层"续传"。

## 二、第一层:传输层自动重连(frpc 自愈)

frpc 断线后不能干等着,要自己爬起来:

- **loginFailExit = false**:连不上/断了**永不退出进程**,进入指数退避重连(第一次等 1s、第二次 2s、4s…封顶),网络一恢复就自动连上;
- **进程守护**:万一 frpc 整个崩溃,由 NSSM(Windows 服务)或 systemd(Linux)**5 秒内自动拉起**;
- 重连动作 = **重新三次握手**,建立一条全新隧道(和首次连接本质相同)。

> 实测:47 上停掉 frps 8 秒再启动,本地 frpc 约 5 秒内自动重连成功。

## 三、第二层:应用层断点续传(HTTP Range)

隧道恢复 ≠ 下载任务自动续上。下载中断后要"从断点继续、不重头来",靠 **HTTP Range**:

```
下载中断前已拿到:0 ~ 10,485,759 字节
恢复时请求:Range: bytes=10485760-          ← 从断点要起
服务器回:206 Partial Content + Content-Range: bytes 10485760-…/2615192587
```

**前提**:服务端支持 Range(FileBrowser 实测支持,回 `Accept-Ranges: bytes`);客户端能发 Range(浏览器下载列表点"恢复",或 Motrix/IDM/迅雷自动重试续传)。

**两种续传体验**:
- 浏览器:断后手动点"恢复"(发 Range 从断点继续);
- 下载器(Motrix/IDM/迅雷):自动重试 + 自动续传 → 全自动。

## 四、完整性怎么保证:拼接 + 校验

续传拿到的是若干"片段",拼接后要验证无损:

- 服务端给的都是原始文件字节(单文件下载),拼接顺序 = 字节偏移;
- **md5 对比**:把下载结果与源文件算 md5,一致 = 无损。
- 实测:断前 1MB + 断后 1MB(经重连续传)拼接,与源文件前 2MB **md5 一致**。

## 五、哪些"不能续传"(重要)

- **文件夹/多选 → zip 打包下载**:服务器边压缩边流式生成,**不支持 Range**,断了重新打包、从头下。→ 大文件分享一律用**单文件**形态。
- **正在写的文件 / 实时流**:同理难续。

## 六、本项目整套抗抖动设计一览

```
网络抖/断
   │
   ├─ 传输层:frpc 指数退避自动重连(NSSM/systemd 兜底)── 秒级恢复隧道
   ├─ 应用层:朋友下载点"恢复"/下载器自动续传 ── Range 从断点继续
   └─ 校验层:md5 对拍确认无损
```

## 带走三句话

1. 断链后要**两层**恢复:传输层重连(新隧道)+ 应用层续传(Range 从断点要);
2. 续传的前提是服务端支持 Range 且客户端会发 Range;
3. zip 打包下载不能续,大文件用单文件。
