# 计网实战课 · 第五课:端口、Socket 与长连接/心跳

> 配套:第二课(连接/四元组)、第四课(穿透)。本课把"程序怎么用网络"讲细。

## 一、Socket:程序嘴里的"网络接口"

TCP/IP 是内核实现的。程序要收发数据,靠操作系统给的接口——**Socket(套接字)**。可以把它想成:程序拿一个"电话筒(Socket)",拨号(connect)或等来电(bind+listen+accept),然后对着话筒读写。

服务端一套标准动作:

```
socket()    ← 拿一个电话筒
bind()      ← 给话筒挂一个门牌(IP:端口,如 47 上 0.0.0.0:8081)
listen()    ← 开始等电话(监听)
accept()    ← 有电话进来,接起来 → 生成一个新 socket 专门服务这位客人
              (原始那个 socket 继续监听,接待下一个)
```

> 关键:一个 `listen` 的 socket 同时能 accept 出**无数**新 socket(每个=一条独立连接)。这就解释了"一个端口能服务几千人":人人有自己的 socket 连接,靠四元组区分。

## 二、四元组:凭什么不串

每条连接 = `(源IP, 源端口, 目的IP, 目的端口)`,四元组相同才算同一条连接。两台机器间可以有很多连接,只要端口不同就不混。

```
A 浏览器 (A机:50001 → 47:8081)
B 浏览器 (B机:50002 → 47:8081)
C 同一浏览器开两个标签(同一 IP,但源端口不同:50003/50004 → 47:8081)
→ 全是不同连接,各回各家
```

## 三、长连接 vs 短连接

- **短连接**:用一次就断(传统 HTTP:每次请求新建、响应完关闭)。开销大:每次都要三次握手。
- **长连接**:建立后反复用,靠**心跳**保活。本项目 frp 隧道就是长连接:frpc 与 frps 之间一条常驻连接,一用到底。

## 四、心跳与保活:怎么知道"还活着"

网络不是可靠的,连接可能"静悄悄死掉"(中间设备断电、链路断但没收到 FIN/RST)。光等没用,要主动探活:

- **心跳(应用层)**:每隔几秒发一个小包(本项目 frp 每 10s 心跳、30s 无响应判死)。
- TCP 也有底层 keepalive(默认很久,应用常自做心跳更灵敏)。
- 发现对方死 → 释放这条连接 → 走"重连"流程(下一课)。

## 五、端口是稀缺资源?绑定与冲突

- 端口 0~65535(16 位)。
- **监听端口**:一台机器上"正在 listen"的同一 TCP 端口同一时刻只能一个(第二个进程会报 `Address already in use`)。→ 所以 frp 占着 47 的 443 后,想加 HTTPS 得先给它挪。
- **临时端口(源端口)**:主动发起连接时,内核从高位端口池随机分配一个,用完可复用,不稀缺。
- TCP 与 UDP 端口互相独立;IPv4/IPv6 端口互相独立。

## 本项目里的对照

```
47:  nginx listen 8081;frps listen 443(0.0.0.0:443)
本地:filebrowser bind 127.0.0.1:8085;frpc 主动 connect 47:443(源端口随机)
fbproxy bind 127.0.0.1:8086(只服务本机 nginx 回源)
```

## 带走三句话

1. 程序用 **Socket** 上网:服务端 bind+listen+accept,客户端 connect;
2. 一条监听能 accept 无数连接,靠**四元组**区分谁是谁;
3. **长连接 + 心跳**用来"一条线用到底并感知生死"(frp 隧道就是)。
