# 计网实战课 · 第七课:带宽、上下行、码率与无线

> 配套:第一课(MTU/MSS)、第三课(状态码)。本课解释本项目那些"数字"到底怎么来、卡在哪。

## 一、几个量的定义(先分清)

- **带宽(bandwidth)**:链路的"容量上限",单位 bps(bit/s)。运营商说的 100M = 100Mbps = 每秒 100 兆比特。
- **吞吐(throughput)**:实际能跑到的速率,通常 ≤ 带宽。
- **换算提醒**:8 bit = 1 Byte。`100Mbps ÷ 8 = 12.5MB/s`(注意大小写 B)。本项目"5~6MB/s"≈ 40~48Mbps。

## 二、上行 vs 下行

- 宽带通常**下行大、上行小**(家用看视频为主):千兆宽带下行 ~940Mbps,上行常只有 30~50Mbps。
- **网盘给别人下载 = 吃你的上行**。你的上行是瓶颈,所以朋友下载 ≈ 你上行速度。

## 三、瓶颈链路(最窄段决定一切)

端到端吞吐 = 路径上**最慢的那一段**。

```
朋友 ← 47(200M 出网)← 隧道 ← 你电脑上行(校园网 ~40M)← 磁盘
                   瓶颈在这里 ←────────┘
```

47 带宽再大也没用,数据得先从你这边"流出去"。这也解释了"把数据放云端(47)就快、放本地就受上行限制"。

## 四、实测定位瓶颈

- 局域网测(排除外网)vs 公网测:哪段是瓶颈一眼看出。
- 本项目实测:朋友下载 ≈ 你上行的 4.3MB/s≈34Mbps,说明瓶颈就是你上行这一段;电脑↔路由器的网线/无线不是瓶颈(瓶颈在上游的无线 WAN / 校园网)。

## 五、码率与在线播放(和带宽什么关系)

- **码率(bitrate)**:视频每秒多少比特 → 决定画质与文件大小:`码率 × 时长 = 大小`。
- **在线流畅播放前提:带宽 ≥ 码率**(播放器每秒要拿到那么多数据才不卡)。
- 例子:`17G ÷ 30s ≈ 4.5Gbps` 码率 vs 你 40Mbps 上行 → 在线播必然卡,只能下载。
- 服务器要不要"编解码":FileBrowser 纯搬运(渐进播放),解码在朋友浏览器;真·多码率流媒体(网飞/Jellyfin)才需要服务器**转码**。

## 六、无线为什么"抖"

- 信号 dBm:越接近 0 越好(-45 好、-70 差);信号决定协商速率→吞吐。
- 无线是**共享介质** + 干扰 + 距离/遮挡 → 速率上下跳(你的 26↔52Mbps)。
- 802.11 有帧聚合(A-MPDU)提升效率,但对 TCP 透明(TCP 只看到 1460B 段)。
- 2.4G 穿墙好但干扰大、慢;5G 快但穿墙差。

## 七、别让一个流量吃死全家:QoS/流控

- 朋友下载占满你的上行 → 你自己上传卡。
- **CAKE/流控**:路由器按需分配带宽,一人下载不拖垮全家(本项目 AX3000T 已配 CAKE,~110Mbps 动态分配)。

## 带走三句话

1. 区分**带宽/吞吐/码率**;8bit=1Byte;
2. 端到端被**最窄段**卡住:网盘下载瓶颈 = 你上行,不是 47;
3. 在线流畅 = 带宽 ≥ 码率;无线天生抖动,用流控别让单流量吃死全家。
