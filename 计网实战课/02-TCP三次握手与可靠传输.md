# 计网实战课 · 第二课:TCP 三次握手与可靠传输

> 配套:第一课(数据包与分层)。前置概念:端口、连接(见正文【答问】)。

## 前置答问:端口会串吗?端口是什么?

- **端口 = 机器内部给程序的"门牌号"**(0~65535),数据到机器后靠它分发。
- 完整定位是「**IP:端口**」:IP 找机器,端口找机器上的程序。
- 一个端口号同一时刻**只能被一个"监听"占用**(别人再 listen 会报 Address already in use),但**能同时服务成千上万连接**——每个连接由**四元组**唯一区分:

```
(源 IP, 源端口, 目的 IP, 目的端口)
A 来:(A机IP, 50001, <SERVER_IP>, 8081)
B 来:(B机IP, 50002, <SERVER_IP>, 8081)
→ 两条独立连接,互不串
```

- 类比:一个柜台(8081 监听)同时接待很多客人(连接),柜员按号办事。
- 细节:TCP 与 UDP 是分开的房间号;IPv4/IPv6 各自独立。两个 **TCP** 服务抢同一端口不行。

## frpc / frp 是什么?

frp(Fast Reverse Proxy)是开源内网穿透工具,两个角色:

| | 跑在哪 | 干什么 |
|---|---|---|
| frps(server) | 47(有公网 IP) | "公网总机",开 443 等分机拨入 |
| frpc(client) | 你电脑(NAT 后) | 主动拨到 frps,把本地 8085 服务挂到公网 |

类比:frps = 云总机,frpc = 你家分机。外人访问 frps 的 8087 → 沿隧道转给 frpc → frpc 再转给本地 filebrowser。

## 本课主题:TCP 面向连接 + 三次握手 + 可靠传输

### 一、TCP 是"打电话",不是"寄信"

| | 寄信(UDP 风格) | 打电话(TCP 风格) |
|---|---|---|
| 开始前 | 直接寄 | **先拨号,对方接才通** |
| 中间 | 丢了不管 | 会说"再说一遍" |
| 结束 | 无告别 | **要说再见** |

TCP 发数据前先确认"你在、我也在、能互收",建立明确"连接",这就是**三次握手**。

### 二、三次握手:为什么偏偏三次?

```
小明(filebrowser)                 小红(朋友浏览器)
 ① SYN "我要发数据,你听着吗?" ──►
 ② ◄── SYN+ACK "我听着!我也要发,你听着吗?"
 ③ ACK "收到,都确认了,开传!" ──►
 ════ 连接建立,开传 1460B×178万 ════
```

- ① 确认小红接收能力在;
- ② 同时回"收到你"(ACK)+ 反问"你能收我的吗"(SYN);
- ③ 小明确认"我收到小红的回答了"。

**为什么不是两次**:小明需要双向确认(我发的你收到 ✓,你发的我也收到 ✓)。只握两次,小明不知道自己的回答小红听没听到。三次后两边都确认"你↔我"双向畅通。

> 本项目里 frpc 每次启动与 frps 之间就这样握手建隧道;断线重连 = 重新拨号、重新握手。

### 三、可靠传输四件套:凭什么一字不差

1. **序号(Sequence Number)——治乱序**
   每字节有编号,包带"我从第 N 字节开始"。接收方不看到达顺序、只按序号重新排队。乱序也能拼回。

2. **确认(ACK)——报进度**
   接收方回 ACK:"你发到第 N 字节为止我都收到了"。

3. **超时重传——治丢失**
   发送方发完开计时器,到点没等来对应 ACK 就重发(数据坏了被丢也算丢失)。丢了哪块补哪块。

4. **滑动窗口——别一个个等**
   "发一个等一个 ACK"太慢;一次发一大把,在途多少个由窗口决定。**吞吐 ≈ 窗口 ÷ 延迟**:窗口越大单位时间传得越多。

外加 TCP 头的**校验和**:数据被改坏 → 当丢失 → 重传。

### 四、串进你的下载 / 断链是什么

```
连接建立 → 按窗口发一大批(带序号)
接收方按序排好 → 回 ACK 报进度
某包坏了/丢了 → 不确认到它 → 计时器到点 → 只重发那一块
全齐 → 完整交浏览器,一字不差
```

**断链**:传输中网络断 → 双方等不到 ACK,连接"死亡" → 序号/窗口状态作废 → frpc 需**重新三次握手**开新连接;已下载部分靠 **HTTP Range(206)** 从断点字节续上。= 传输层重连 + 应用层续传双层配合。

## 带走三句话

1. TCP 发数据前先**三次握手**,确认双向可通,建立连接(像打电话);
2. 可靠性靠 **序号(乱序)+ ACK(进度)+ 超时重传(丢失)+ 窗口(效率)** 四件套;
3. 断链 = 连接死 → 重新握手;续传靠应用层 Range。
